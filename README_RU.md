# Telegram Study Logger

Локальный журнал выбранного Telegram-чата с автоматической расшифровкой голосовых,
видеокружков и обычных видео. После однократной настройки отдельные окна или
ручной экспорт не нужны: открываешь привычный Telegram, модуль начинает работу.

Это первая версия с исходным кодом и установочными скриптами, а не расширение
официального клиента и не готовые подписанные `.exe` / `.dmg`.

[English README](README.md) · [Результаты проверок](VALIDATION.md)

## Два режима выгрузки — версия 0.2.0

Выбор предлагается при установке. При обновлении сохранённой установки выбирается
только режим: повторно вводить `api_id`, код или пароль не нужно.

| Режим | Как работает | Главные файлы |
| --- | --- | --- |
| История за N дней | Догружает N календарных дней, включая сегодня. Поддерживает единую выгрузку за последние N дней, которая обновляется при новых сообщениях и со сменой даты | `history_7_days.md`, `history_7_days.jsonl` для N=7 |
| Ежедневно | При включении догружает весь текущий день с 00:00. Обновляет его в течение дня. После полуночи создаёт следующий дневной файл, вчерашний сохраняется | `2026-10-05.md`, `2026-10-06.md`, всегда актуальный `today.md` и соответствующие `.jsonl` |

N=7 означает **сегодня и шесть предыдущих дат**, а не последние 168 часов.
Границы дней определяются выбранным часовым поясом. N=0 в режиме истории означает
всю доступную историю (`history_all.md` / `.jsonl`). Дневные файлы сохраняются и в
режиме истории; старые файлы не удаляются при сокращении N.

В ежедневном режиме после смены даты `today.md` содержит только новый день.
Если разговоров ещё нет, файл пустой по содержанию сообщений. Расшифровка записи
поздно вечером может закончиться завтра: она дополнит файл даты **отправки** записи.

Если компьютер/Telegram были закрыты, работа возобновляется при следующем запуске;
пропущенные дни с момента включения режима догружаются. В полночь при выключенном
компьютере файл физически создаться не может.

## Разовая выгрузка периода

После первоначальной настройки можно отдельно выгрузить последние N дней или
только сегодняшний день. Разовый запрос **не меняет выбранный автоматический режим**,
догружает старые сообщения из Telegram и ждёт обработки доступных голосовых/видео.
Неподдерживаемые или недоступные записи отмечаются ошибкой.

На Linux/macOS:

```bash
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy export --days 7
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy export --today
```

Файлы создаются в `Documents/TelegramStudy/<ID чата>/reports/`, например
`history_2026-09-29_2026-10-05.md` и `.jsonl`. Команда может выполняться долго,
если за период много записей. Текстовая выгрузка появляется до завершения расшифровок
и обновляется по мере обработки. До завершения команды Telegram-обработчик временно
приостанавливается; затем наблюдатель возобновляет обычное логирование. Если его
автозапуск ранее был отключён, команда сама не включает его обратно.

## Переключение режима без повторного входа

На Linux/macOS:

```bash
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy mode daily
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy mode history --days 7
```

Команды безопасно останавливают текущий обработчик на время изменения настроек.
Данные аккаунта и выбранный чат остаются прежними. При работающем наблюдателе
обработка возобновится автоматически. Для меню с выбором режима:

```bash
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy settings
```

`settings` также включает автозапуск. На Windows замени Python в командах на
`%LOCALAPPDATA%\TelegramStudyLogger\runtime\Scripts\python.exe` (в PowerShell —
`& "$env:LOCALAPPDATA\TelegramStudyLogger\runtime\Scripts\python.exe"`).

Для обновления версии 0.1.0 распакуй новый архив и снова запусти установщик своей ОС:
он остановит старый модуль, обновит код и предложит выбор режима, сохранив сессию.

## Что происходит автоматически

- Наблюдатель запускается при входе в ОС и раз в 3 секунды проверяет процесс Telegram.
- Когда Telegram работает, запускается синхронизация только выбранного чата.
- История за выбранный период догружается при первом запуске. Затем догружаются
  сообщения, пришедшие за время отсутствия, и поступают новые сообщения.
- Голосовые, видеокружки и видео с аудиодорожкой обрабатываются локальной моделью
  Whisper. Для каждой записи сохраняются текст, язык, длительность и временные сегменты.
- Файлы по дням обновляются примерно раз в 3 секунды; сама расшифровка может занять дольше.
- Полное завершение Telegram останавливает обработчик после 15 секунд ожидания.
  Если вычисление не завершилось за дополнительные 45 секунд, процесс завершается,
  а незавершённая запись обрабатывается заново при следующем запуске.
- Закрытие окна в трей оставляет Telegram работающим — логирование продолжается.
- Небольшой наблюдатель остаётся в фоне без окон. Повторный запуск защищён блокировками.

Telegram Desktop для Linux/Windows/macOS поддерживается на уровне распознавания
процесса. В список также включено имя `Telegram` для клиента macOS. Telegram Web,
телефон, секретные чаты и работа при выключенном компьютере не поддерживаются.
Для нестандартного клиента добавь имя процесса в `process_names`.

## Что нужно один раз

1. Python 3.11–3.13, рекомендуется 3.12. Интернет для установки зависимостей и загрузки модели.
2. Свой `api_id` и `api_hash`: открой [my.telegram.org](https://my.telegram.org),
   войди и выбери **API development tools**. Заполни форму приложения, например
   `Telegram Study Logger`, short name `tgstudy`, platform `Desktop`.
   Это **Telegram API**, ключ OpenAI не нужен.
3. Вход по номеру телефона, коду Telegram и паролю 2FA, если он установлен.
   Все секреты вводятся локально. Не присылай код, пароль, `api_hash` или файл сессии в чат.
4. Выбор чата по имени, папки выгрузки и режима. Для новой установки по умолчанию
   предлагается ежедневный режим; в режиме истории можно задать N или `0` для всей истории.
5. Загрузка модели. `small` — настройка по умолчанию; `base` легче, `medium` требует
   больше памяти и времени. Размер загрузки зависит от модели. CPU используется без CUDA.

Код и пароль не сохраняются; авторизация хранится в отдельном `account.session`.
Она появится в Telegram → Настройки → Устройства как **Telegram Study Logger**.
Это дополнительная сессия твоего аккаунта. Копировать данные официального клиента не нужно.
Если Telegram отклоняет выдачу кода стороннему клиенту, повторный запуск не обходится
другими способами: проверь доступность API и авторизацию.

## Установка на Arch Linux

Распакуй архив и открой терминал в папке `telegram-study-logger`:

```bash
python3 --version
bash install-linux.sh
```

Если системный Python новее 3.13 или отсутствует подходящая версия, можно использовать
`uv` **только для установки Python**:

```bash
sudo pacman -S uv
uv python install 3.12
TGSTUDY_PYTHON="$(uv python find 3.12)" bash install-linux.sh
```

`uv` не запускается во время логирования. Нужен рабочий графический сеанс,
поддерживающий XDG Autostart. У GNOME/KDE он есть; для самостоятельного оконного
менеджера см. раздел автозапуска ниже.

## Установка на Windows

1. Установи Python 3.12 x64 с [python.org](https://www.python.org/downloads/).
   Включи Python Launcher (`py`).
2. Распакуй ZIP полностью, затем открой `install-windows.cmd`.
3. Пройди настройку в открывшемся окне. После этого окно можно закрыть.

Автозагрузка создаётся в пользовательской папке Startup. Запуск идёт через
`pythonw.exe`, поэтому терминал при обычной работе не появляется. Нужен Windows
Script Host (обычно включён). В организациях он может быть отключён политиками.
Скрипт не требует прав администратора. Версия рассчитана на Windows x64;
Windows ARM64 и 32-bit здесь не проверены.

## Установка на macOS

Установи Python 3.12 с [python.org](https://www.python.org/downloads/), распакуй ZIP
и в терминале из папки проекта выполни:

```bash
bash install-macos.command
```

Если `python3` указывает на другую версию, укажи полный путь к Python 3.12:

```bash
TGSTUDY_PYTHON=/Library/Frameworks/Python.framework/Versions/3.12/bin/python3 bash install-macos.command
```

Создаётся пользовательский LaunchAgent. В настройках macOS разреши фоновую работу,
если система её запросит. На macOS доступ к папке Documents также может потребовать
разрешения: можно выбрать другую папку при настройке.
Используется CPU, отдельное приложение распознавания и Homebrew не нужны.

## После установки

Открывай Telegram как обычно. Установщик активирует наблюдатель сразу и настраивает
автозапуск для следующих входов в ОС. Папку с распакованным исходным кодом после
успешной установки можно переместить: пакет копируется в постоянное окружение.

По умолчанию выгрузка находится в:

```text
Documents/TelegramStudy/<ID выбранного чата>/
```

Для каждого дня создаются:

| Файл | Назначение |
| --- | --- |
| `2026-10-05.md` | Переписка и расшифровки для чтения или отправки в чат анализа английского |
| `2026-10-05.jsonl` | Одно сообщение на строку, точные даты/ID/автор/длительность/сегменты |
| `chat.json` | Название чата, твой ID, часовой пояс и версия формата |

`JSONL` — собственный формат журнала, а не побайтовая копия `result.json` из штатного
экспорта Telegram. Markdown подходит для чтения и передачи в инструмент анализа
английского без преобразования. Время хранится одновременно в UTC и выбранном
часовом поясе. Установщик предлагает часовой пояс компьютера; если определить
его не удалось, предлагает `UTC`. Подтверди или измени его при настройке.

Текст сообщения (`text`) и автоматически распознанная речь (`transcript`) разделены,
поэтому голосовой output не нужно считать повторно как письменный. Есть флаг
`forwarded`. Определить, какие обычные сообщения написаны ИИ или скопированы,
автоматически нельзя. Сам input/output в этой версии не вычисляется.

Расшифровки могут содержать ошибки: для анализа произношения/грамматики сверяй
сомнительные места с оригиналом. Первоначальная длинная история будет обрабатываться
последовательно; текст появится раньше всех расшифровок.

## Проверка после установки

1. Открой Telegram и выбранный чат.
2. В течение нескольких секунд должен запуститься обработчик. Дождись догрузки текста.
3. Отправь короткое голосовое и видеокружок с несколькими английскими фразами.
4. В сегодняшнем `.md` сначала появится запись со статусом `pending`, затем расшифровка.
5. Полностью выйди из Telegram, вновь открой его и проверь, что записей-дублей нет.

Журнал не отправляет сообщения, не пересылает записи ботам и не вызывает методов
пометки сообщений прочитанными. Для распознавания внешние сервисы не используются;
при первом скачивании модели выполняется запрос к Hugging Face, затем обработка локальная.
Связь с серверами Telegram всё равно нужна для получения новых сообщений и медиа.

## Команды обслуживания

Обозначение `PYTHON` ниже — Python из установленного окружения:

| ОС | Путь |
| --- | --- |
| Linux/macOS | `~/.local/share/telegram-study-logger/runtime/bin/python` |
| Windows | `%LOCALAPPDATA%\TelegramStudyLogger\runtime\Scripts\python.exe` |

Например, на Linux:

```bash
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy status
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy paths
```

Остальные команды:

```text
PYTHON -m tgstudy uninstall  — отключить автозапуск и остановить процессы
PYTHON -m tgstudy setup      — выбрать другой чат / заново войти / поменять параметры
PYTHON -m tgstudy settings   — меню выбора режима без повторной авторизации
PYTHON -m tgstudy mode daily — включить ежедневную выгрузку
PYTHON -m tgstudy mode history --days 7 — поддерживать выгрузку последних 7 дней
PYTHON -m tgstudy export --days 7 — разово выгрузить 7 дней из Telegram
PYTHON -m tgstudy export --today — разово выгрузить текущий день
PYTHON -m tgstudy install    — снова включить автозапуск
PYTHON -m tgstudy retry      — повторить записи, закончившиеся ошибкой
PYTHON -m tgstudy export     — пересоздать файлы из локальной базы
```

Перед `setup` выполни `uninstall` и подожди до минуты, пока обработчик остановится.
Команды `mode`, `settings`, `retry` и `export` управляют остановкой самостоятельно.
`setup` и `settings` включают автозапуск; остальные команды сохраняют прежнее состояние
автозапуска.

В Windows PowerShell путь вызывается так:

```powershell
& "$env:LOCALAPPDATA\TelegramStudyLogger\runtime\Scripts\python.exe" -m tgstudy status
```

### Автозапуск для самостоятельного оконного менеджера

Если твой сеанс не обрабатывает XDG Autostart, добавь в его конфигурацию запуск:

```bash
~/.local/share/telegram-study-logger/runtime/bin/python -m tgstudy watch
```

В Hyprland это строка `exec-once =` с полным путём; в i3 — `exec --no-startup-id`.
Установка через XDG не гарантирует запуск в таких сеансах. Не нужно добавлять
отдельный ручной запуск при каждом открытии Telegram.

## Настройки и ограничения

`paths` покажет папку данных. `config.json` содержит параметры:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `export_mode` | `daily` для новой установки | `daily` или `history`; для изменения лучше использовать команду `mode` |
| `history_days` | 30 до задания своего N | N календарных дней в единой выгрузке; 0 = вся история |
| `model` | `small` | Модель faster-whisper или путь к совместимой локальной модели |
| `language` | `null` | Автоопределение; `"en"` для фиксированного английского |
| `cpu_threads` | `2` | Ограничение нагрузки на процессор |
| `max_media_mb` | `100` | Лимит одной записи, можно увеличить |
| `transcribe_videos` | `true` | Распознавать обычные видео; видеокружки и голосовые всегда включены |
| `poll_seconds` | `60` | Период догрузки истории; новые сообщения приходят через события |
| `process_names` | Telegram/Telegram.exe/telegram-desktop/Telegram Desktop | Точные имена процессов клиента |

После ручного изменения настроек останови модуль через `uninstall`, затем запусти
`install`. При смене часового пояса используй `setup`, чтобы пересчитать даты
при повторном чтении выбранного диапазона истории.

- Только один выбранный чат логируется одновременно. При выборе другого старый
  архив остаётся отдельно. Новый выбор не удаляет ранее сохранённые сообщения.
- Изменения сообщений во время работы обрабатываются. Для правок во время отсутствия
  периодически перепроверяются последние 200 сообщений. Старые правки вне этого
  диапазона восстановятся при повторном импорте через `setup` с нужной глубиной истории.
- Удалённые сообщения не удаляются из локального архива. Сообщение, удалённое до
  первой синхронизации, восстановить невозможно; удалённое до скачивания медиа
  остаётся без расшифровки со статусом ошибки.
- Фото/стикеры/документы отмечаются типом, их содержимое не архивируется. Исходные
  голосовые и видео скачиваются временно и удаляются после обработки; сохраняется текст.
- Крупные записи сверх `max_media_mb`, защищённые медиа, видео без аудиодорожки,
  повреждённые файлы и ограничения Telegram дают явный статус ошибки.
- При сетевых сбоях записи повторяются с задержкой. После шести обычных ошибок
  требуется команда `retry`; Telegram FloodWait откладывает обработку по требованию сервера.
- SOCKS-прокси из переменных окружения поддерживается загрузчиком моделей.
  Настройки прокси официального Telegram не наследуются MTProto-модулем автоматически.
  В этой версии для Telegram API нужен прямой доступ; если он заблокирован, модуль
  не заработает, даже когда официальный клиент работает через свой прокси.
- Несколько устройств могут вести свои локальные архивы, но их базы не объединяются
  автоматически. Синхронизация файлов между компьютерами в комплект не входит.

Локальная сессия предоставляет доступ к аккаунту, поэтому не публикуй папку данных.
На Linux/macOS используются приватные права файлов. На Windows данные лежат в
пользовательской папке; отдельного шифрования в этой версии нет. Для отключения
доступа можно завершить сессию в Telegram → Устройства и отключить автозапуск.

## Для разработки

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install '.[test]'
.venv/bin/python -m pytest -q
```

На Windows используй `.venv\Scripts\python.exe`. В комплекте есть GitHub Actions
workflow для проверки на Ubuntu, Windows и macOS при загрузке проекта в свой репозиторий.
Выполненные здесь проверки и их ограничения описаны в `VALIDATION.md`.

Документация использованных компонентов:
[Telegram API](https://core.telegram.org/api/obtaining_api_id),
[Telethon](https://docs.telethon.dev/en/stable/),
[faster-whisper](https://github.com/SYSTRAN/faster-whisper).
